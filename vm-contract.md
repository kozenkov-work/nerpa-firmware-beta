# Контракт исполняемого файла Нерпы

## Общий формат (beta)

Тело исполняемого файла представляет собой набор секций, каждая секция начинается с `*`, строки в каждой секции разделены символом перевода строки.

1. `*config` - [параметры конфигурации](#параметры-конфигурации). `<ID_ПАРАМЕТРА>:<ЗНАЧЕНИЕ>`
2. `*variables` - список переменных. `<ID_ПЕРЕМЕННОЙ>:<type>`([enum](#type---типы-значений))
3. `*strings` - список значений типа строка. `<ID_СТРОКИ>:"<СТРОКА>"`
4. `*code` - [вызовы инструкций](#список-инструкций-beta). `<НОМЕР_СТРОКИ>:<ИНСТРУКЦИЯ> <АРГУМЕНТ1> <АРГУМЕНТ2> ...`

## Список инструкций (beta)

`data_stack` слева направо, вершина справа. Аргументы снимаются с вершины, результат кладётся обратно.

### Стек

- `CONST type value` - на `data_stack` `value` типа `type`([enum](#type---типы-значений))
- `POP` - снять вершину с `data_stack`
- `DUP` - на `data_stack` копию вершины

### Арифметика

- `MATH operation_id` - операция `operation_id`([enum](#operation_id---id-математической-операции)), снять и положить на `data_stack` по ней

### Сравнение

- `EQ` - `a == b` [*]
- `LT` - `a < b`
- `GT` - `a > b`

### Поток исполнения

- `JMP line` - перейти к `line`
- `JMPF line` - если false, перейти к `line`
- `CALL line` - на `call_stack` место вызова, перейти к `line`
- `RET` - с `call_stack` место вызова, вернуться к нему

### Переменные

- `GET variable_id` - на `data_stack` значение переменной `variable_id`
- `SET variable_id` - установить переменной `variable_id` значение с `data_stack`

### Ввод/вывод

- `HOST function_id` - функция `function_id`([enum](#function_id---id-функции-хоста-beta)), снять и положить на `data_stack` по ней

## Параметры конфигурации

Тип значения из `type`([enum](#type---типы-значений)).

0. Номер строки функции `setup` (`number`, default: 0)
1. Номер строки функции `loop` (`number`, required)
2. Является ли Лёня пидорасом (`bool`, default: true)

## Enum-ы

### `type` - Типы значений

0. `number` - число
1. `bool` - логическое, в `value` 0 - false, 1 - true
2. `string` - строка, в `value` id строки в `*strings`
3. `null` - пустое значение, в `value` 0

### `function_id` - Id функции хоста (beta)

0. `debug_print` - строка в консоль
1. `pin_mode` - номер пина, режим
2. `digital_write` - bool в состояние пина
3. `digital_read` - состояние пина -> bool
4. `analog_write` - number 0-1 в состояние пина
5. `analog_read` - состояние пина -> number 0-1

### `operation_id` - Id математической операции

0. `number_plus` - `a + b` [*]
1. `number_minus` - `a - b`
2. `number_mult` - `a * b`
3. `number_div` - `a / b`
4. `string_plus` - `a` с `b` на конце
5. `bool_and` - оба true
6. `bool_or` - хотя бы один true
7. `bool_not` - не `a`

[*]: `a` - глубже (левое, первое), `b` - вершина (правое, второе).

## Стеки

1. `data_stack` - стек данных
2. `call_stack` - стек вызовов функций (тип элемента: число, то же которым описаны номера строк)

## Важное

1. Секции идут в порядке, описанном в контракте.
2. Функции, вызываемые через `CALL`, всегда возвращают одно значение. Если функции нечего вернуть, она возвращает `null`([enum](#type---типы-значений)).
3. Формулировки "на `стек`" / "с `стек`" означают положить на стек и снять со стека, если не указано иного.

## Выполнение программы

1. VM один раз вызывает функцию `setup`. Если параметр 0 отсутствует, используется строка 0.
2. Затем VM бесконечно вызывает функцию `loop`, пока хост не запросит остановку через `shouldStop`.
3. Возвращаемые значения `setup` и `loop` отбрасываются после каждого вызова.
4. Параметр 1 с номером строки `loop` обязателен. Обе строки должны существовать в `*code`.
5. На `RET` VM проверяет, что функция оставила на `data_stack` ровно одно новое значение относительно момента вызова. Отсутствие результата или лишние значения являются ошибкой.
6. Завершение кода функции без `RET` является ошибкой.

## Компиляция и прошивка ESP32

Прошивка собирается отдельно от desktop-версии через ESP-IDF 6.1. Цель — обычный ESP32.
Программы не встраиваются в прошивку: они читаются из корня SD-карты, подключенной
по SPI (CS=5, MOSI=23, MISO=19, CLK=18). После выбора файла в меню «Выбор программы»
он загружается из `/sdcard`, разбирается `Tokenizer` и выполняется в `VM`. Вывод
`debug_print` отображается на экране и дублируется в UART. Дисплей SSD1306 128x64
подключается по I2C (SDA=21, SCL=22, адрес `0x3C`), функциональные кнопки используют
GPIO 13, 14, 27 и 26. Отдельная кнопка RESET на GPIO25 вызывает GPIO-прерывание по
спадающему фронту; ISR только выставляет флаг, а VM проверяет его каждые 32 инструкции
и после каждого `loop`: первое нажатие останавливает выполнение и оставляет консоль
открытой, повторное нажатие или BACK возвращает к списку файлов. После изменения файла на
SD-карте перепрошивать устройство не нужно.

Из корня репозитория:

```bash
# Сборка
./esp32.sh build

# Сборка, прошивка и вывод программы из UART в консоль компьютера
./esp32.sh -p /dev/ttyUSB0 flash monitor

# Только мониторинг уже прошитого устройства
./esp32.sh -p /dev/ttyUSB0 monitor
```

Вместо `/dev/ttyUSB0` нужно указать порт платы, если он другой. Выйти из monitor:
`Ctrl+]`.

Скрипт использует `~/.espressif/tools/activate_idf_v6.1.sh`. Если ESP-IDF установлен
в другом месте, путь можно задать через переменную `IDF_ACTIVATE_SCRIPT`.
